# 第三轮攻击模型与安全不变量

建模日期：2026-10-28（Asia/Singapore）。审计基线：
`59105290820bcbfd4e0336a2e7713006a461527f`；Kadb 只读基线：
`49a88b14e9b731e4c086c920eb74664450c79d9f`。
这是本轮在修改任何生产密码学源码之前建立的模型；后续发现可以修订假设，
不能通过修订模型排除已发现的实际攻击。

## 系统、资产与信任边界

三个发布模块的计算均在纯 Kotlin commonMain：RFC 会话位于
`src/commonMain/.../rfc/`，Legacy 位于 `legacy/src/commonMain/`，数学、哈希、
角色和熵接口位于 `primitives/src/commonMain/`。RFC 和 Legacy 的公开状态机
与派生语义分离，共享原语不构成协议自动协商。

秘密资产包括应用口令及派生标量 w、Legacy passwordHash/passwordScalar、
临时 x/y、未掩码点和共享点 K、含秘密的 TT、Ke/Ka/KcA/KcB、哈希/KDF 的
中间状态及尚未完成认证的 Legacy 64-byte 输出。公开消息、公开群参数、
相应上下文允许公开的身份/AAD及其长度，不被误记为秘密。秘密处理不能因
某个测试用了公开固定向量就获得豁免。

信任边界依次是：应用的输入规范化/MHF与可信 CSPRNG → 会话所有权和 API
契约 → 曲线/哈希实现 → 编译器/JIT/运行时/操作系统 → 传输和完整应用认证。
另有源码、依赖下载、构建 runner、发布归档、来源身份和消费者解析的供应链
边界。公开 API 无法证明一个返回合法字节的熵源具有熵；这个前提必须由调用方
满足，错误长度和显式熵源异常则是库应当 fail closed 的输入。

Kadb 使用客户端/Alice、Legacy HARDENED、TLS exporter 拼入口令、HKDF 和
AES-GCM。TLS 接受未预信任证书时，不能提前把握手成功等同于设备身份认证；
具体认证条件由本轮完整配对链审查确定。Kadb 源码只读，不将上游消费者通过
当作应用端迁移或真实设备配对成功。

## 攻击者能力分层

| 标识 | 能力 | 不能默认赋予的额外能力 |
| --- | --- | --- |
| N0 被动网络观察者 | 读取链路上的包长、时序和可见流量 | 不直接得到已加密 TLS 的应用明文、进程内密钥或诚实端熵 |
| N1 主动网络 MITM | 丢弃、替换、重放、延迟、重排、注入；可尝试终止两条独立 TLS 会话 | 不能假设两条 TLS exporter 相同，不能默认知道配对码 |
| P0 恶意协议对端 | 选择全部点编码/确认值/公开上下文，发起大量会话 | 不自动知道诚实端的 w/x 或获得已认证状态 |
| C0 并发/重入调用者 | 以受控调度重叠公开方法、在 callback 重入、触发非法顺序 | 不把应用主动提供弱随机或任意内存篡改隐藏成网络攻击 |
| T0 远程时序观察者 | 重复交互并统计响应时延/错误行为 | 不默认能够剔除网络、TLS、调度和速率限制噪声 |
| T1 同机运行时观察者 | 高精度计时、GC/JIT/分配信息及模型允许的缓存/分支观察 | 与 N0/N1 分开评估，需说明实际观测接口和共驻条件 |
| M0 内存取证者 | 获得 heap dump、残留内存或进程权限 | 不因 owned arrays 已清零而假设其读不到旧副本；该能力强于网络观察 |
| S0 供应链攻击者 | 提供同名错误版本、替换模块/产物/元数据、污染仓库或构建输入 | GitHub、编译器或上游发布账号完全失陷需单列，不能由自报摘要排除 |

## 必须验证的安全性质

| 编号 / 不变量 | 信任假设与实现位置 | 反证方法 | 初始剩余不确定性 |
| --- | --- | --- | --- |
| SP-01 无正确秘密不能取得已认证会话 | 合格熵、正确应用预处理；`Rfc9382Session.confirm`、Kadb 的最终认证条件 | 错密码/身份/AAD/角色、反射、跨会话拼接、错误 MAC、无效 PeerInfo | 有限攻击用例不等于 PAKE 证明；下游完整链另审查 |
| SP-02 未确认材料不能被当作认证完成 | RFC 只由 confirm 返回 Ke；Legacy 调用方遵守 unconfirmed 契约 | 调用顺序模型、API 返回和下游用点审查 | Legacy 返回 ByteArray，类型系统本身不能强制全部调用者遵守契约 |
| SP-03 消息不直接泄露 w/x/K/会话秘密 | 离散对数假设、正确群参数/算法；publicMessage/sharedPoint/transcript | 独立点/标量中间值、低阶/混合阶/退化值、异常日志检查 | 编译产物和侧信道需独立验证 |
| SP-04 不增加离线口令验证能力 | 不复用 x/y，口令域和 MHF 参数正确；固定 M/N 的离散对数未知 | 重复熵、重放、恶意点、Legacy 历史模式反例 | 不合格熵可破坏前提；必须揭示而不能声称库能认证熵质量 |
| SP-05 秘密相关执行不形成可利用泄露 | 编译器/运行时不会破坏算术调度；ModMath/点运算/hash/KDF | 源码、真实生成代码/JIT/机器码及受控统计计时 | 全平台严格恒定时间尚未证明；不显著结果不能升级为证明 |
| SP-06 绑定身份/角色/上下文/通道 | 应用传入正确身份/AAD；Kadb 使用当前连接 exporter | 同密码异身份/AAD、nil 身份前提、版本/角色混淆、双 TLS splice | TLS 提供者/导出语义需逐平台核对 |
| SP-07 恶意输入不能产生错误成功 | 严格 RFC 解码、相应群语义、cofactor、确认比较 | 非规范点、全部低阶点、非法长度、标量边界和有限 fuzz | Legacy 历史宽松解码不是 RFC 安全校验；语义须独立说明 |
| SP-08 失败终止且不再释放秘密 | session 串行使用；AtomicInt guard 与 cleanup 有正确线性化 | 确定性屏障、重入、非法方法序列、有界状态探索、故障注入 | 已完成调用的合法返回不能被后续 destroy 撤回；物理擦除不由逻辑状态证明 |
| SP-09 同密码不能掩盖上下文错误 | 身份隐含模式仅用于真正隐含身份；协议无自动回退 | 同密码不同身份/模式/会话、错方向确认、消息 interleaving | 应用遗漏必要 AAD 是应用集成前提，需从下游实际调用判断 |
| SP-10 发布物可追溯到不可变输入 | 可信来源摘要、明确构建配置与下载来源；发布/消费者门禁 | 错坐标/版本、缺失变体、项目替换、伪造内容、源码/产物不一致 | 结构检查和自报 hash 不认证恶意生产者；构建依赖/runner 信任必须公开 |

## 验收方法与裁决规则

先冻结输入，再由不同审查者从原始代码和规范形成发现，之后交叉质疑。
所有实验使用可公开的固定或合成测试秘密。每项发现保留攻击能力、影响、
最小输入、确认程度、严重度、修复前后证据和平台范围；未经复现的假设不能
作为已确认漏洞。确认的 Critical/High 以及关键未解疑点阻断相应安全门禁。
Medium 必须明确风险暴露与处置，不能仅列为以后再看。

Gate A 评估功能与互操作，必须明确 RFC §7 时序条款不能由向量替代；
Gate B 还要求可信候选、正确未确认密钥边界、无已知下游安全阻塞及逐平台
风险范围；Gate C 需要生产运行时、应用集成和专业审计达到相应证据水平。
三层分别允许 PASS / CONDITIONAL PASS / FAIL / NOT VERIFIED。旧 CI 只
证明旧 SHA 上实际执行的范围，不替代新测试/生产改动后的验证。

不以增加测试数量、重构规模或绿 CI 数量评价本轮成功。保留纯 Kotlin 的
工程偏好不能高于已确认的安全需要；架构替代方案可以提出和验证边界，
未经授权不整体替换实现、不修改 Kadb、不合并 main、不发布正式包。
